# Установка на твой Bothost

Ты уже используешь Bothost. Для этой версии не нужно покупать второй сервер или отдельный домен. Обновляем существующий проект, чтобы сохранить его постоянный диск. Бесплатный адрес выдаёт сам Bothost, если включить домен; доступность адреса зависит от тарифа и настроек проекта.

## 1. Подготовь обновление

1. Скачай `SMM_Web.zip` и распакуй на компьютере.
2. В старом боте нажми «Стоп» для СММ и «Остановить всё» в Менеджере. Уже начатый запрос/отправка могут завершиться — дождись результата.
3. В Bothost открой **тот же проект**, в котором сейчас работает бот. Не удаляй проект и постоянный диск.
4. Если у тебя есть резервная копия хостинга — сделай её перед обновлением. Новая версия также автоматически сохранит данные в `/app/data/backups` при первом запуске.
5. Останови локальную копию на компьютере, если она работает с тем же BOT_TOKEN.

## 2. Загрузи исходники в GitHub

Используй репозиторий, указанный в текущем проекте Bothost. У тебя последним был `sasaarkelan-code/Telegram_bot`; проверь ссылку в настройках проекта.

Открой репозиторий → **Add file → Upload files**. На компьютере перетащи ВСЁ содержимое распакованного архива, включая папку `smm`, и сохрани в ветку `main`. При загрузке сохраняй вложенные папки. Один ZIP, оставленный в репозитории, GitHub и хостинг автоматически не распакуют.

В корне должны быть:

```text
main.py
requirements.txt
Dockerfile
backup_data.py
smm/hosting.py
smm/webapp.py
smm/web/index.html
smm/web/app.js
smm/web/style.css
smm/web/theme-init.js
smm/web/manifest.webmanifest
smm/web/sw.js
```

Если старый репозиторий был плоским (store.py, ui.py и остальные лежали в корне), новые модули находятся в папке `smm/`. Новый `main.py` выберет именно эту папку. Старые одноимённые файлы в корне не используются; удалять их до успешного запуска не требуется. Обязательно обнови корневые `main.py` и `requirements.txt`.

Не загружай в GitHub свои `config.json`, `credentials.json`, `host.json`, `manager.session`, `smm.sqlite`, `.env` или содержимое `/app/data`.

## 3. Настройки существующего проекта

Открой шестерёнку проекта. Выбери:

| Поле | Значение |
|---|---|
| Язык | Python |
| Версия | Python 3.11 или новее |
| Ветка | main |
| Главный файл | main.py |
| Использовать домен | Включено |
| Внутренний порт | 8000 |
| Собственный Dockerfile | Можно включить: файл Dockerfile находится в корне |

В ENV оставь существующие BOT_TOKEN и OWNER_ID. Добавь/проверь:

| Переменная | Значение |
|---|---|
| SMM_DATA_DIR | /app/data/smm — именно прежняя папка данных |
| SMM_WEB_ENABLED | 1 |
| SMM_WEB_COOKIE_SECURE | 1 |
| SMM_WEB_URL | https://АДРЕС_ИЗ_ПАНЕЛИ_BOTHOST |
| MANAGER_ENABLED | 0, если аккаунт менеджера ещё не подключён |

PORT хостинг передаёт из поля «Порт». Он должен быть 8000. Сервер слушает `0.0.0.0:$PORT`; сам 443 внутри контейнера указывать не нужно.

SMM_WEB_URL — реальный адрес, выданный хостингом: без завершающего пути и без `/#home`. Не пиши буквально «АДРЕС_ИЗ_ПАНЕЛИ_BOTHOST». Если адрес пока не выдан, временно оставь переменную отсутствующей, включи домен, получи адрес и затем впиши его. Эта переменная нужна для ссылки в боте и проверки запросов сайта.

Если менеджер уже подключён, сохрани его старые MANAGER_ENABLED, MANAGER_API_ID, MANAGER_API_HASH и файл сессии. Не меняй их на нули.

## 4. Пересобери и запусти

После загрузки кода выполни обновление/пересборку из Git, затем запусти проект. Обычная кнопка перезапуска старого образа может не забрать новые исходники — нужна именно сборка с обновлённым репозиторием.

В журнале должны появиться:

```text
Резервная копия перед веб-обновлением: /app/data/backups/...
Веб-панель 2.1.0: 0.0.0.0:8000. Для входа отправь боту /web.
SMM Manager 2.1.0 запущен...
```

Запускается один процесс — и сайт, и Telegram-бот, и планировщики. Второй бот с тем же токеном создавать не нужно.

## 5. Бесплатный адрес и HTTPS

После включения «Использовать домен» скопируй ссылку, которую показывает Bothost. Зона может быть `bothost.tech` или `bothost.ru` — используй именно выданную ссылку. Произвольный адрес вида `my-studio.bothost.tech` сам по себе работать не начнёт.

Bothost направляет HTTPS-запросы на внутренний порт приложения и управляет сертификатом. Проверь, что адрес открывается по `https://`. Это бесплатный поддомен хостинга, а не отдельный личный домен `.ru`/`.com`. Для твоей панели его достаточно.

Официальная документация: https://bothost.ru/docs/domains-and-ports

## 6. Первый вход

1. В своём Telegram-боте отправь `/web` или нажми «🌐 Веб-панель» в главном меню.
2. Бот напишет логин и одноразовый код.
3. На сайте введи username и код. Можно вводить username с @ или без; если username нет, введи свой Telegram ID.
4. Код действует 5 минут и работает один раз. Новый `/web` аннулирует предыдущий ещё неиспользованный код.
5. Проверь каналы, очередь, выбранную модель и лимиты. При обновлении они берутся из старой базы. После проверки нажми «Продолжить», если СММ на паузе.

Если бот пока не может выдать код, в приватном терминале проекта:

```sh
python main.py web-code
```

Он выдаст код владельца на 5 минут; логин — сохранённый username или OWNER_ID. Код никому не пересылай. Это запасной способ, не обычная процедура входа.

## 7. Управление с телефона

Открой сайт на телефоне → войди → Настройки → «Установить приложение».

Android/Chrome: меню ⋮ → «Установить приложение» или «Добавить на главный экран».

iPhone/Safari: «Поделиться» → «На экран Домой»; если есть переключатель «Открывать как веб-приложение», оставь его включённым.

Сайт откроется отдельным окном с иконки «Студия». Сверху — СММ / Менеджер, снизу — кнопки выбранного раздела. Подробности в `MOBILE_AND_LOGIN_RU.md`.

## 8. Если что-то не открывается

| Симптом | Что проверить |
|---|---|
| 502 / 504 | Домен включён, порт в панели 8000, в журнале сервер слушает этот же порт |
| После входа снова экран кода | Открывай HTTPS. На публичном сервере SMM_WEB_COOKIE_SECURE=1 |
| «Недопустимый источник запроса» | SMM_WEB_URL совпадает с текущим адресом сайта, без пути и без завершающего слеша |
| Нет команды /web | Запущена старая сборка. Пересобери образ с обновлёнными main.py и smm/ |
| Пропали старые каналы/модель | Проект смотрит в другую папку. Проверь SMM_DATA_DIR; не подключай новую пустую базу вместо старой |
| Нет ИИ | Нужны прежние credentials.json, host.json и сохранённая модель в той же папке данных |
| Не работает менеджер | Черновики работают сразу; отправка и поиск требуют отдельной Telegram-сессии |
| Нет места на резервную копию | Освободи место или сохрани приватный бэкап вне диска хостинга; не удаляй рабочую базу |

Архив в этой переписке — готовый исходный код. Установку на твоём аккаунте Bothost нужно выполнить по этим шагам; архив сам не меняет сервер.
