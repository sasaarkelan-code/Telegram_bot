# SMM Manager 1.3.0 — обновление существующего бота на Bothost

Архив подготовлен под репозиторий sasaarkelan-code/Telegram_bot:
все рабочие Python-файлы находятся в корне. main.py поддерживает и исходную
структуру с папкой smm. Python 3.11+, запуск: `python -u main.py`.

## Обновление без второго бота и дубликатов

1. Останови существующий бот в Bothost. Сохрани резервную копию папки данных
   `/app/data/smm` средствами панели. При копировании файлов базы бот должен быть
   остановлен; сохраняй всю папку, включая smm.sqlite-wal, если он есть.
2. Распакуй SMM_Deployka.zip на компьютере. Загружать ZIP как один файл в GitHub
   не нужно: хостинг должен увидеть распакованные main.py, fashion.py и остальные.
3. Открой https://github.com/sasaarkelan-code/Telegram_bot, ветку main.
   Через Add file → Upload files загрузи содержимое архива в корень и сохрани
   коммит. Файлы с тем же именем и путём обновляют существующие. Не создавай
   папку SMM_Deployka или Telegram_bot внутри репозитория. Папку tests загружай
   как папку, если загружаешь тесты.
4. В карточке СУЩЕСТВУЮЩЕГО бота Bothost выполни обновление из Git с пересборкой
   и запусти его. Обычный перезапуск без получения нового коммита код не обновляет.
   Git URL: https://github.com/sasaarkelan-code/Telegram_bot.git,
   ветка main, главный файл main.py. Собственный Dockerfile и домен не нужны.
5. Оставь прежние BOT_TOKEN, OWNER_ID и `SMM_DATA_DIR=/app/data/smm`.
   Данные, вход и базу в GitHub загружать не нужно.
6. В журнале проверь строку `SMM Manager 1.3.0`.
   В Telegram открой СММ → Фильтры → канал одежды: «Автопоиск WB/Ozon» включён.
   Проверь «Лимиты». Если бот был на паузе, возобнови его своей кнопкой.

Не создавай нового бота и не переноси заново credentials.json. Обновление
сохраняет владельца, совладельцев, модель (включая gpt-5.6-sol), каналы,
бюджеты, очередь, расход ИИ и вход. Самостоятельно паузу не снимает.
Старые ZIP в репозитории не используются как исходники при запуске main.py.
На компьютере второй экземпляр с тем же Telegram-токеном должен быть выключен.

Если в репозитории уже ЕСТЬ папка smm с рабочим кодом, обновляй модули именно
в ней; не смешивай две версии. Этот плоский архив рассчитан на показанную
структуру твоего репозитория без папки smm.

## Изменённые рабочие файлы

Новый файл: fashion.py.
Обновлены: ai.py, config.py, editor.py, engine.py, store.py, ui.py,
hosting.py и __init__.py. Остальные рабочие файлы включены для полной сборки.
README.md, TEST_REPORT.txt и tests содержат инструкцию и проверки обновления.
Если загружаешь только исправления, перечисленные рабочие файлы обязательны;
остальные файлы твоего репозитория удалять не нужно.

## Автопоиск одежды без ручного каталога

За 40 минут до выхода включённого канала бот ищет недостающие категории:
куртка/пуховик, свитер/верх, брюки, зимняя обувь, шапка и сумка.
Принимает прямые ссылки WB/Ozon из источников поискового ответа.
Сохраняет находки по каналу на 12 часов; после частичного сбоя продолжает с
недостающих категорий. При смене темы/стиля/фильтров старые находки не подмешиваются.
При готовой базе без истории нужен лишь запрос сборки. Для следующих образов
бот подбирает свежие альтернативы, чтобы не повторять тот же комплект.

Перед сборкой проверяет публичные предложения на карточках. В итоговую сумму
входит весь комплект; цены не занижаются ради бюджета. При недоступной карточке
показывает, что цена/наличие не подтверждены, и требует ручной проверки.
Ручной каталог остаётся дополнительным вариантом, заполнять его не обязательно.
Блокировки площадок бот не обходит. Веб-поиск должен быть доступен выбранной
модели и аккаунту; локальные лимиты не предоставляют этот доступ.

## Лимиты после обновления

| Ограничение бота | Новый предел |
| --- | ---: |
| Токены за день | 300 000 |
| Токены за последние 5 часов | 180 000 |
| Токены на канал за день | 200 000 |
| Запросы за день | 100 |
| Запросы за час | 40 |
| Этапы одной подборки одежды | 10 |
| Поисковые вызовы внутри одного запроса одежды | 4 |
| Время поискового запроса | 150 секунд |

Обновление один раз увеличивает существующие общие лимиты до этих значений.
Если твои значения уже больше, они сохранятся. Последующие изменения в меню
и отключение автопоиска сохраняются после перезапуска. Предел этапов относится
к одному выходу и сохраняется даже при ручном повторе. Каждый этап проходит
тот же учёт input/output; неизвестный расход и аварийная остановка сохранены.
Предел поисков и времени контролируется клиентом; это не гарантия точного
потолка расхода уже отправленного запроса. Вход через подписку не поддерживает
серверный max_output_tokens. Лимиты подписки этим обновлением не меняются.

## Изображения и публикация

Через текущее подключение подписки генерация изображений не поддерживается.
Увеличение текстовых лимитов это не меняет. Автоматизированы поиск,
сохранение товаров и сборка предложений; готовую картинку пока нужно прикрепить.
Для полной автоматизации изображения потребуется отдельный генератор/API.
Платные запросы и отдельный API-ключ эта сборка автоматически не включает.
Промпт двух взрослых моделей в одном комплекте доступен в предложении;
для точного соответствия генератору нужны фотографии реальных вещей.

Посты публикуются после одобрения. Неполные комплекты и неподтверждённые цены
не проходят одобрение без исправления/проверки владельцем. Обязательность
картинки сохраняется. Менеджер кампаний сохраняет прежние функции.

## Проверка сборки

Установка: `pip install -r requirements.txt`.
Локальные проверки: `python -m unittest discover -s tests -t . -q`.
Тесты используют фиктивные ответы ИИ/площадок, настоящие запросы не оплачиваются.
На живом Bothost и с твоим входом эта версия не проверена.
