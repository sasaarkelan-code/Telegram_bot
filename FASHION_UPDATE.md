# Одежда: что исправлено в 1.5.0

Раньше требовались минимум шесть отдельных запросов на категории и ещё один
на сборку. Неудачные категории и попытки удешевления увеличивали число запросов
до десяти. Проверялись до 24 карточек, даже если нужен был один образ.

Новая схема:

1. Использовать готовый сохранённый образ, если его ещё не предлагали.
2. Если готового нет, ИИ одним запросом выбирает стиль и весь комплект:
   верхняя одежда, верх, брюки, обувь, шапка, сумка.
3. Код открывает карточки выбранного образа, проверяет реальные публичные цены,
   наличие, ссылки и сумму. Отдельного запроса к ИИ на эти проверки нет.
4. При необходимости одним дополнительным запросом заменить только отсутствующие,
   недоступные или слишком дорогие вещи. Остальные сохраняются.
5. Сохранить основной образ в предложениях. Запасной, если он был получен сразу,
   оставить на следующий выход. Нового запроса ИИ для него не нужно.

Один основной запрос + максимум одно исправление на заявку. Это предел
вызовов модели, не гарантия, что любой поиск обязательно найдёт все товары.
Если рынок/поиск не дали данные, бот сохраняет частичный результат и объясняет
причину. Бесконечного перебора и поисков отдельно по всем категориям нет.

## Экономия

- Готовые образы и найденные товары живут в сохранённых находках до 24 часов.
- Проверяется только основной образ: обычно 6 карточек, а не все альтернативы.
- Неудачная публичная проверка не повторяется в течение часа.
- Запасной образ проверяется, когда действительно понадобится.
- Для выбранной gpt-5.6-sol в одежде используется низкая глубина рассуждений.
  Модель не заменяется, ИИ новостей и менеджер не перенастраиваются.
- Старый каталог без готовых образов можно использовать: один запрос выбора
  по готовым ID без веб-поиска, если хватает подходящих вещей в бюджете.
- Показатели последней заявки доступны в фильтрах канала: запросы, токены, причина.

В локальных тестах полный холодный подбор занимает 1 вызов модели, ремонт —
всего 2, сохранённый готовый образ — 0 новых вызовов. Это измерения на
подставных ответах, не замер расхода твоей подписки. Фактическая экономия токенов
зависит от ответа модели, поисковой выдачи и доступности карточек.

## Защита без потери результата

Для одной заявки есть отдельный бюджет с резервом: по умолчанию 24 000 токенов.
Если не хватает резерва на следующий запрос, он не отправляется.
Достижение предела заявки или дневного предела ИИ канала одежды не выключает
подготовку остальных каналов. Фактический известный расход выше резерва закрывает
дальнейшие запросы этой заявки, а не выбрасывает полученный полный образ.

Общие лимиты бота и защита при неизвестном расходе сохраняются. Если после
корректно завершённого ответа достигается общий предел, полный образ остаётся
в предложениях, а следующие запросы/публикации останавливаются. Проверка
карточек, не успевшая завершиться до общей паузы, остаётся неподтверждённой.
Снимать эту отметку автоматически бот не будет.

Подключение через подписку не поддерживает max_output_tokens/max_tool_calls.
Поэтому программные резервы, время и число поисков не являются абсолютным
серверным потолком уже начатого запроса. Весь полученный usage учитывается,
включая output tokens с внутренними рассуждениями. Официальные ограничения:
https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations
https://developers.openai.com/api/docs/guides/reasoning

## Обновление твоего Bothost

1. Останови рассылки менеджера, если они работают, и останови бот в панели.
2. Сохрани резервную копию постоянной папки данных /app/data/smm.
3. Распакуй ZIP на компьютере и замени файлы в том же GitHub-репозитории
   sasaarkelan-code/Telegram_bot, ветка main. Архив целиком как файл не загружай.
4. Изменённые рабочие файлы: fashion.py, ai.py, budget.py, editor.py, config.py,
   store.py, ui.py, hosting.py, __init__.py. Они лежат в корне, как в твоём репозитории.
   Если у тебя сохранена исходная папка smm, модули нужно заменить в ней.
5. Обнови существующий бот из Git и пересобери. Журнал должен показать
   SMM Manager 1.5.0. Новых ключей, API или аккаунтов для оптимизации не требуется.

Не меняй SMM_DATA_DIR=/app/data/smm, не заменяй базу и файлы входа архивом.
Общие лимиты, выбранная модель, очередь, каналы, менеджер, совладельцы и расход
сохраняются. Настройки одежды одноразово уменьшаются до новых значений;
если у тебя уже установлен более строгий предел, он остаётся.

Потраченная квота подписки после обновления не восстанавливается. Общая пауза
сама не снимается. Проверь её причину в «Лимитах» и возобнови работу, когда
доступ/квота позволяют. Старые исчерпанные попытки не обнуляются: новая схема
используется для следующих заявок в окне подготовки по расписанию.

Для публикации по-прежнему нужны одобрение и картинка, если она обязательна
для канала. Если WB/Ozon не отдают публичную цену, требуется проверка человеком.
Оптимизация не включает генерацию изображений и не снимает эти требования.
